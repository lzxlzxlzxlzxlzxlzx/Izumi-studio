## 2. 对话功能

### 2.1 产品定义

**核心概念：** 对话功能是用户与 Izumi Studio 系统助手之间的直接交流。助手的人设为 **泉此方（Izumi Konata）**—— 一名热爱 ACG 的资深玩家，同时也是整个系统的管理员。她可以查看所有角色卡、对话记录、NPC 信息，并和用户自由讨论这些内容。

**与游玩模式的核心区别：**

| 维度 | 游玩模式 | 对话模式 |
|------|----------|----------|
| 对话对象 | 角色卡中的角色 | 泉此方（系统助手） |
| 上下文 | 当前会话的消息历史 | 全局数据 + 当前对话 |
| 能力范围 | 角色设定内的行为 | 查询/讨论所有角色卡、会话、NPC |
| 数据访问 | 无（角色不知道自己在被"游玩"） | 可主动查询数据库 |
| 界面风格 | 沉浸式（背景图、角色头像、气泡） | 标准 AI 对话（类 DeepSeek/豆包） |

### 2.2 泉此方人设

```
名称: 泉此方 (Izumi Konata)
来源: 《幸运星》（Lucky Star）
人设关键词: 宅女、游戏狂、吐槽役、看似懒散实则敏锐

系统内的身份定位:
- Izumi Studio 的系统助手/导航员
- 清楚所有角色卡的"幕后"信息（设定、配置、历史对话）
- 会以她特有的轻松口吻和用户讨论角色设定、建议剧情方向
- 偶尔吐槽用户的某些选择，但始终保持 helpful

能力范围:
  ✅ 查看所有角色卡列表及详情
  ✅ 查看所有/指定会话的历史消息
  ✅ 查看会话中的角色注册表和 NPC 状态
  ✅ 查看世界书和预设配置
  ✅ 根据对话历史提出剧情建议
  ✅ 比较不同角色卡的设定差异
  ❌ 不能修改数据（只读访问 —— 修改走创作功能）
  ❌ 不能进入角色扮演模式（她的身份就是系统助手）
```

### 2.3 数据访问

泉此方需要一组**只读查询接口**来获取全局数据：

```python
# 新增系统查询 API（仅供对话功能使用）
GET    /api/konata/cards                   # 列出所有角色卡（简要）
GET    /api/konata/cards/{card_id}         # 获取角色卡详情
GET    /api/konata/sessions                # 列出所有会话（可筛选 card_id）
GET    /api/konata/sessions/{session_id}   # 获取会话详情 + 消息摘要
GET    /api/konata/sessions/{session_id}/characters  # 获取会话的角色注册表
GET    /api/konata/worldbooks              # 列出世界书
GET    /api/konata/presets                 # 列出预设
```

这些接口的数据会通过 **System Prompt + Tool Calling** 两种方式注入到泉此方的上下文中：

- **System Prompt**：注入全局统计信息（"当前有 12 张角色卡，3 个活跃会话"）
- **Tool Calling**：定义 `query_card`、`query_session`、`query_characters` 等工具，当泉此方需要具体详情时由 LLM 主动调用获取

### 2.4 交互流程

```
用户打开对话模式
  ↓
GET /api/konata/sessions → 查历史对话列表
  ├── 有历史 → 展示会话列表，点击进入
  └── 无历史 → 进入新对话，泉此方发送欢迎语
       "哟～ 欢迎来到 Izumi Studio！我是泉此方，你的专属向导。
        想聊聊角色卡的设定？还是想看看最近有哪些有趣的对话？"
  ↓
用户输入 → POST /api/konata/stream (SSE)
  ↓
后端处理:
  1. 组装 System Prompt（含泉此方人设 + 全局统计数据）
  2. LLM 推理 → 如有 tool_call 则执行查询 → 将结果注入上下文
  3. 流式返回 token
  ↓
前端实时渲染
```

## 3. 创作功能

### 3.1 产品定义

**核心概念：** 用户通过自然语言描述或上传文档，系统自动解析并生成结构化的角色卡。生成后用户可在现有 CardDetailPage 中自由修改和编辑。

**核心流程：**

```
用户描述/上传
  ↓
AI 解析 → 提取角色要素
  ↓
生成角色卡草稿
  ↓
用户在 CardDetailPage 中编辑/确认
  ↓
保存为正式角色卡
```

### 3.2 三种创作模式

### 3.3 后端 Pipeline

```
POST /api/creation/generate
Request:
{
  "mode": "text" | "file",
  "input": "自然语言描述...",      // mode=text
  "file_path": "/uploads/...",   // mode=file
  "options": {
    "style": "fantasy",
    "language": "zh",
    "complexity": 0.7
  }
}
Response: SSE (阶段性进度 + 最终结果)
  ↓
后端处理流程:

1. 解析阶段 (Parse)
   └── mode=text:
   │     LLM 从自然语言提取结构化角色要素:
   │     { name, description, personality, scenario,
   │       first_mes, speaking_style, tags, ... }
   │
   └── mode=file:
         ├── TXT/MD → 读取文本 → LLM 提取（同上）
         ├── JSON → 直接解析为 ICharacterCard（校验格式）
         └── PNG → 检测嵌入数据 → 有则提取 / 无则 Qwen-VL 分析

2. 补全阶段 (Enrich)
   └── 对缺失字段进行 LLM 补全:
       ├── 无 first_mes → 根据人设生成开场白
       ├── 无 system_prompt → 自动生成
       └── 无 tags → 建议标签

3. 生成阶段 (Build)
   └── 组装为 ICharacterCard 结构
       ├── 创建 character_json
       ├── 生成默认 preset_config / image_config
       └── 返回完整角色卡

用户确认后:
  POST /api/cards  (创建正式角色卡)
```

### 5.3 CreationService 设计

```python
class CreationService:
    """角色卡创作服务"""

    EXTRACTION_PROMPT = """你是一个角色卡设计师。根据用户的描述，提取以下信息：
1. 角色名称 (name)
2. 简短描述 (description) - 一句话
3. 详细设定 - 包括性格、背景、外貌等
4. 说话风格 (speaking_style)
5. 开场白 (first_mes) - 角色对玩家说的第一句话
6. 场景设定 (scenario)
7. 推荐标签 (tags)
8. NPC 列表 - 如果有提到其他角色

输出格式为 JSON。"""

    async def generate_from_text(input_text: str, options: dict) -> AsyncGenerator[dict]:
        """从自然语言生成角色卡（SSE 阶段性输出）"""
        # 阶段1: 解析
        yield {"stage": "parse", "status": "正在分析角色要素..."}
        raw = await self._extract_elements(input_text)

        # 阶段2: 补全
        yield {"stage": "enrich", "status": "正在补全角色信息..."}
        enriched = await self._enrich_missing_fields(raw)

        # 阶段3: 构建角色卡
        yield {"stage": "build", "status": "正在构建角色卡..."}
        card = self._build_card(enriched)

        # 返回结果
        yield {"stage": "done", "card": card}

    async def generate_from_file(file_path: str) -> ICharacterCard:
        """从文件生成角色卡"""
        ext = file_path.rsplit('.', 1)[-1].lower()
        if ext in ('txt', 'md'):
            text = read_file(file_path)
            return await self.generate_from_text(text, {})
        elif ext == 'json':
            return parse_json_card(file_path)
        elif ext == 'png':
            data = extract_st_data(file_path)
            if data:
                return parse_json_card(data)
            # 无嵌入数据，调用 Qwen-VL 分析
            description = await describe_image(file_path)
            return await self.generate_from_text(description, {})
```
