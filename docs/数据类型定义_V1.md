## 1. 角色卡域

角色卡是游玩模式的核心数据载体，包含角色定义、对话配置、资源绑定等完整信息。

### ICharacterCard

**作用：** 完整角色卡定义，是游玩模式选择和使用的基本单位。
**会话初始化：** 系统读取 `character.npcs` 中所有 `start_active=true` 的角色模板，在新建会话时自动实例化为 `IStoryCharacter` 并注册到会话的 `ICharacterRegistry`。

```typescript
interface ICharacterCard {
    /** 唯一标识 */
    id: string;
    /** 角色名称 */
    name: string;
    /** 简短简介（展示在角色卡封面上） */
    description: string;
    /** 标签列表，用于过滤和分类 */
    tags: string[];

    /* ====== SillyTavern V3 兼容 ====== */
    /** 角色卡规范版本（如 "chara_card_v3"），用于导入验证 */
    spec: string;
    /** 规范版本号 */
    spec_version: string;
    /** 扩展数据（兼容 ST V3 的 data.extensions） */
    extensions: Record<string, unknown>;

    /* ====== 封面与头像 ====== */
    cover: ICoverInfo;
    avatar: IAvatarInfo;

    /* ====== 角色定义 ====== */
    character: ICharacterDefinition;

    /* ====== 提示覆盖 ====== */
    /** 覆盖全局 System Prompt（可选） */
    system_prompt: string | null;
    /** 注入到消息历史末尾的持续指令（可选） */
    post_history_instructions: string | null;
    /** 注入到特定深度的角色专属提示（可选） */
    depth_prompt: IDepthPrompt | null;

    /* ====== 资源绑定 ====== */
    /** 绑定的世界书 ID 列表（可绑定多个，世界书为全局共享资源） */
    worldbook_ids: string[];
    /** 绑定的预设名称（默认预设，预设为全局共享资源，为 null 时使用 preset_config） */
    preset_name: string | null;

    /* ====== 对话默认参数 ====== */
    /** 未指定预设时的回退配置 */
    preset_config: IPresetConfig;

    /* ====== 图片生成配置 ====== */
    image_config: IImageConfig;

    /* ====== 扩展配置 ====== */
    /** 角色卡专属 Author's Note */
    authors_note: IAuthorsNoteConfig | null;
    /** 绑定的 Quick Reply Set ID 列表 */
    quick_reply_set_ids: string[];
    /** 绑定的 Regex Script ID 列表 */
    regex_script_ids: string[];

    /* ====== 状态管理 ====== */
    status: ECardStatus;
    /** 当前版本号 */
    version: number;
    /** 创建时间 */
    created_at: string;
    /** 发布时间 */
    published_at: string | null;
}

enum ECardStatus {
    DRAFT = 'draft',
    PUBLISHED = 'published',
}
```

### ICharacterDefinition

**作用：** 角色的核心定义数据，直接参与上下文组装。`npcs` 字段中的角色模板是会话初始角色注册表的来源。

```typescript
interface ICharacterDefinition {
    /** 角色名（对话中显示的名称） */
    name: string;
    /** 角色详细描述（性格、背景、外貌等），注入上下文 */
    description: string;
    /** 性格摘要（简短标签式描述） */
    personality: string;
    /** 场景设定（对话发生的初始背景） */
    scenario: string;
    /** 说话风格描述 */
    speaking_style: string;
    /** 背景故事（完整性背景，可被 worldbook 触发扫描） */
    background: string;

    /* ====== 开场白 ====== */
    /** 默认开场白 */
    first_mes: string;
    /** 备选开场白列表 */
    alternate_greetings: string[];

    /* ====== 示例对话 ====== */
    /** 用于 few-shot 的对话示例（<START> 格式） */
    mes_example: string;

    /** 创作者备注（不注入上下文，仅展示） */
    creator_notes: string;

    /** 角色模板列表（`start_active=true` 的角色在会话开始时自动出场） */
    npcs: INPC[];
}
```

### INPC

**作用：** 角色卡内定义的角色模板。新建会话时，`start_active=true` 的角色自动实例化进入角色注册表；`start_active=false` 的角色可由模型通过 skill 动态激活。属性完全灵活，由角色卡创作者定义键和值。

```typescript
interface INPC {
    /** 角色名称 */
    name: string;
    /** 初始属性集合（完全灵活，键值由角色卡创作者决定，如 age, gender, occupation 等） */
    attributes: Record<string, string | number | boolean>;
    /** 是否在会话开始时自动出场 */
    start_active: boolean;
    /** 简要描述（供世界书引擎参考，不作为注入上下文的直接内容） */
    description: string;
}
```

## 2. 世界书域

世界书管理一组条目的关键词触发规则，是游玩模式中动态注入上下文的核心机制。

### IWorldBook

**作用：** 世界书元数据，控制条目扫描和注入的全局行为。

```typescript
interface IWorldBook {
    /** 唯一标识 */
    id: string;
    /** 世界书名称 */
    name: string;
    /** 简介 */
    description: string;
    /** 原著名称（如涉及 IP 时） */
    ip_name: string;

    /** 绑定的 UI 组件 Schema */
    ui_components: IUIComponentSchema | null;

    /* ====== 扫描与触发配置 ====== */
    /** 扫描深度：最近 N 条消息中匹配关键词 */
    scan_depth: number;
    /** 条目总 token 预算 */
    token_budget: number;
    /** token_budget 占 max_context 的比例（备用计算方式） */
    token_budget_ratio: number;
    /** 是否启用递归扫描（已激活条目的 content 也参与下一轮扫描） */
    recursive_scanning: boolean;
    /** 最大递归步数 */
    max_recursion_steps: number;
    /** 关键词匹配：大小写敏感 */
    case_sensitive: boolean;
    /** 关键词匹配：全词匹配 */
    match_whole_words: boolean;
    /** 插入策略 */
    insertion_strategy: EInsertionStrategy;
    /** 最少激活数（低于此数则自动补充） */
    min_activations: number;
    /** 预算溢出时是否告警 */
    overflow_alert: boolean;

    /* ====== 条目列表 ====== */
    entries: IWorldEntry[];

    created_at: string;
    updated_at: string;
}

enum EInsertionStrategy {
    CHARACTER_FIRST = 'character_first',
    GLOBAL_FIRST = 'global_first',
    EVENLY = 'evenly',
}
```

## 3. 预设域

预设是控制模型行为和对话格式的完整配置包，源自 SillyTavern 的 preset 概念。

### IPreset

**作用：** 完整预设配置，包含模型参数、格式模板和提示条目列表。
**参数覆盖规则：** IPreset 中的模型参数（temperature, max_tokens 等）优先级高于 IModelConfig 中的同名参数。预设参数仅在当前会话生效，IModelConfig 参数是全局默认值。

```typescript
    frequency_penalty: number;
    presence_penalty: number;

    max_tokens: number;

    scenario_format: string;
    personality_format: string;

    /* ====== 提示列表 ====== */
```

## 4. 对话域

**数据层级关系：**

```
角色卡 (ICharacterCard)
 └── 会话 (IChatSession)      ← 用户选择角色卡后创建的对话
      └── 消息 (IChatMessage) ← 会话中的每轮交互
           └── Swipe (ISwipe) ← 同一条消息的备选回复
```

- 一个角色卡下可以有 **多个会话**，会话间相互独立
- 一个会话包含 **多条消息**，用户发送 + 模型回复各算一条
- **消息轮次**定义：用户发一条（role=user）+ 模型回一条（role=assistant）= **一轮**
- 摘要按 **消息轮次** 触发（默认每 10 轮生成一段增量摘要）

### IChatSession

**作用：** 一次对话的元数据，标识对话所属角色、会话级配置覆盖。

```typescript
interface IChatSession {
    /** 唯一标识 */
    id: string;
    /** 所属角色卡 ID */
    card_id: string;
    /** 对话模式 */
    mode: EChatMode;
    /** 会话名称（用户可自定义） */
    name: string;
    /** 使用的开场白索引（0=first_mes, 1+=alternate_greetings[i-1]） */
    greeting_index: number;

    /* ====== 会话级配置覆盖 ====== */
    /** 当前使用的模型 */
    model: string;
    /** 会话绑定的世界书 ID 列表（默认使用角色卡的 worldbook_ids，可在会话级增减） */
    worldbook_ids: string[];
    /** 会话使用的预设名称 */
    preset_name: string;

    /** 会话背景图路径（默认使用角色卡封面图，用户可替换为自定义图片） */
    background_image: string | null;

    /** 父会话 ID（分支对话时记录来源） */
    parent_session_id: string | null;
    /** 分支编号 */
    branch_number: number | null;

    created_at: string;
    updated_at: string;
}
```

### 回溯逻辑

当用户回溯到某条消息时，角色状态的回滚算法：

```
function rollback(card, sessionId, targetMessageIndex):
    // 1. 从角色卡 NPC 模板初始化
    registry = initializeFromCard(card)
    // 2. 加载截至目标消息索引的所有变更日志
    logs = fetchChangeLogs(sessionId, targetMessageIndex)
    // 3. 按顺序重放变更
    for log in logs:
        applyChange(registry, log)
    return registry
```

- 变更日志 **append-only**，回溯只是改变重放截止点，不会丢失数据
- 用户可前进到任意消息索引（反向回溯）
- 任何时候都可从变更日志完整重建角色注册表

### 变更日志存储说明

| 维度 | 说明 |
|------|------|
| 存储位置 | SQLite `character_change_logs` 表，按 `(session_id, message_index)` 复合索引 |
| 重建时机 | 加载会话 / 切换消息时重建 ICharacterRegistry |
| 性能预期 | 单会话变更量通常 < 1000 条，全量回放 < 10ms |
